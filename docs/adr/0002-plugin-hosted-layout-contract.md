# 0002：由宿主托管插件内容区与布局契约

- 状态：提议
- 日期：2026-08-20
- 相关 Issue：[#7](https://github.com/Chengyunlai/my-ssh/issues/7)（跨仓库：`my-ssh` / `my-ssh-plug`）

## 背景

`mysql-manager` 是一个带连接管理、对象树、SQL 编辑器和结果工作区的重型外部插件。当前
插件可以在自身 CSS 中定义整块页面的宽度、背景、溢出和组件样式；MySSH 只提供一个可伸缩
面板容器。结果是插件需要反复猜测宿主布局，容易覆盖顶栏/侧栏边界，并与核心主题产生漂移。

两个仓库独立发布，插件不能直接修改核心仓库。需要一个先在核心落地、再由插件迁移的稳定
宿主契约，同时保留普通插件的兼容性。

## 决定

1. 插件 `panel` 增加可选 `layout`，仅允许 `standard` 与 `workspace`，缺省为 `standard`。
2. MySSH 为每个面板提供 `.plugin-surface` 宿主壳层，统一负责内容区位置、最大边界、溢出、
   层叠隔离和主题 Token；插件不得逃逸该壳层。
3. `workspace` 只表达“允许插件在内容区内部组织复杂工作台”，不授权插件修改 MySSH 外壳；
   侧栏宽度、工具栏高度和滚动区域属于插件内部实现，但必须遵守固定 Token 与尺寸建议。
4. 样式采用宿主语义 Token 加插件根类局部规则，不允许插件注册全局 CSS 或复制宿主主题。
5. 跨仓库变更按核心 Issue/PR → 发布核心版本 → 插件 Issue/PR 的顺序推进。

## 后果

- 核心需要维护一个小而稳定的布局/Token 契约，后续重型插件可以复用。
- 既有插件不必立即修改，缺省 `standard` 保持渲染兼容。
- `mysql-manager` 需要把硬编码主题和全局注入规则迁移到根类与宿主 Token，初次改造有成本。
- 宿主仍不能静态阻止恶意插件读取或写入 DOM，因此这是布局与维护性约束，不是安全沙箱；
  外部插件的能力边界仍由 IPC/API 与加载链路负责。

## 备选方案

- 允许插件完全自定义全屏布局：短期最快，但会持续产生位置、尺寸和视觉漂移，否决。
- 为每种复杂插件单独写核心特例：能快速修一个插件，但不可扩展，否决。
- 只提供设计文档不提供宿主壳层：依赖人工遵守，无法保证溢出和边界，否决。
